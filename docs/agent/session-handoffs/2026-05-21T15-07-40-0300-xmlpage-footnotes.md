## What Worked

- `format_line_text()` now scans PAGE XML line text for bracketed content,
  removes the brackets and note text from the inline line, appends a
  superscript reference, and stores notes in page order.
- `render_footnotes()` writes an ordered footnote list below the `.box` page
  container.
- `collect_text_lines()` computes text width from the visible post-footnote
  text, so long footnote text does not shrink the rendered line.
- The generated layout preserves the original center-origin scaling behavior.
  A `top center` transform origin made the large unscaled PAGE container get
  centered offscreen before scaling, which caused an all-white browser view.
- The inline superscript references now use a muted editorial umber/red,
  Georgia-style serif typography, and a subtle underline so they read as notes
  rather than source text.
- The bottom footnote area is larger and academic-paper-like: transparent over
  the paper surface, separated by a rule, serif, and readable after page scaling.
- OCR lines are now rendered as baseline anchors: `.line` has zero height and
  `.text` is absolutely positioned with `bottom: 0`. This keeps the visual text
  tied to the PAGE XML baseline instead of inheriting normal browser line-box
  offsets.
- `scripts/xmlpage_to_html.py` is import-safe through a `main()` wrapper.
- Targeted unittest coverage passes:
  `python3 -m unittest tests.xmlpage_to_html_test`.
- Regenerated `/Users/kian/Downloads/output.html` from
  `/Users/kian/Downloads/YJUDZXHLPYXPHCIGGIWCUBTU.xml` after the scaling fix and
  after the footnote style and baseline-spacing passes.

## What Failed

- A broad `rg` over `.` hit generated tokenizer outputs and produced noisy
  output. Subsequent exploration used targeted file reads.

## Remaining Questions

- Nested bracket syntax is not defined. The implementation handles ordinary
  non-nested `[note]` spans and leaves empty `[]` inline.
- The script still follows its existing raw HTML behavior for source text and
  lightweight formatting markers. It does not add a new escaping/sanitizing pass.
- No headless browser was available in the repo environment, so final visual
  verification was by generated HTML/CSS inspection rather than screenshot.
